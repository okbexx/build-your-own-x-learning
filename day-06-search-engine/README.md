# Day 6 · Search Engine

## build-your-own-x 对应原始项目地址
- [Build a Search Engine](https://boyter.org/2013/01/code-for-a-search-engine-in-php-part-1/)

## 这是什么
搜索引擎本质上是信息检索系统：它从一批文档中收集内容、建立可查询结构，并在用户输入查询时返回最相关的结果。它不只是“网页上的搜索框”，而是一整套采集、索引、检索和排序流程。这里引用的项目是一个用 PHP 编写的简化教学实现，适合用来理解基本机制，不是生产级搜索平台。

## 怎么使用
- 先按“采集 -> 索引 -> 查询”顺序阅读项目，理解每一步解决的具体问题。
- 准备少量页面或文本样本，观察内容如何被收集、切分并写入索引。
- 输入简单查询词，检查命中文档、匹配逻辑和结果顺序是否符合预期。
- 在跑通最小流程后，再思考真实系统会如何补上增量更新、去重、权限控制和性能优化。

## 核心原理
- 抓取与采集：从网页或文档源收集原始内容，决定抓取范围、更新频率和数据入口。
- 索引构建：把原始文本转换成适合检索的数据结构，避免查询时全量扫描所有文档。
- 分词：将文本拆成词项，通常还会配合大小写归一、停用词过滤和基础规范化。
- 倒排索引：为每个词项记录它出现过的文档、位置和频次，这是高效全文检索的核心结构。
- 查询解析：把用户输入转成可执行条件，例如关键词、短语、布尔逻辑或字段限定。
- 排序：对召回结果计算相关性分数，常见信号包括词频、位置、字段权重、文档质量和新鲜度。
- 检索流水线：系统接收查询，完成解析，在倒排索引中召回候选文档，打分、排序并返回结果。

## 适用场景
- 博客、知识库、文档站、商品目录等需要全文检索的系统。
- 数据规模已经超过简单数据库 `LIKE` 查询的可接受范围。
- 学习信息检索基础，理解搜索系统最小可行实现。

## 不适用边界
- 这个 PHP 教学项目不适合直接承担大规模生产流量、复杂语言处理或分布式检索需求。
- 如果数据很小、查询高度结构化，直接使用数据库索引通常更简单。
- 如果目标是语义问答、推荐或复杂理解，关键词搜索只是基础能力，不是完整方案。

## 为什么它重要
搜索引擎解决的不是“把数据存下来”，而是“让数据在需要时被准确找出来”。一旦文本规模变大，索引结构、查询延迟和排序质量会直接影响系统可用性。理解搜索引擎，就是理解现代信息系统如何把海量文本转成可访问知识。

## 建议延伸
- 对比 Lucene 或 Elasticsearch，理解教学实现与工业实现的结构差异。
- 补充中文分词、短语查询、高亮、分页和增量索引。
- 继续学习 TF-IDF、BM25、拼写纠错、去重和链接分析。
